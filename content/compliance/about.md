## What the SOC 2 audit covered

The Security category, also called the **Common Criteria**, is the mandatory core of every SOC 2 report. It has nine groups. This is what each one means at Teramot, and the policy that governs it.

<div class="tm-cc-grid not-prose">
  <div class="tm-cc"><span class="tm-cc-code">CC1</span><span class="tm-cc-name">Control environment</span><p class="tm-cc-text">A code of conduct, defined security roles, and an Information Security Committee that approves policies.</p><a href="/compliance/Policies/information-security-roles/">Security roles →</a></div>
  <div class="tm-cc"><span class="tm-cc-code">CC2</span><span class="tm-cc-name">Communication and information</span><p class="tm-cc-text">Published security commitments and policies, and open channels to report vulnerabilities or concerns.</p><a href="/compliance/Transparency/security-commitments/">Security commitments →</a></div>
  <div class="tm-cc"><span class="tm-cc-code">CC3</span><span class="tm-cc-name">Risk assessment</span><p class="tm-cc-text">A documented process to identify threats, rate them and track their treatment.</p><a href="/compliance/Policies/risk-management/">Risk management →</a></div>
  <div class="tm-cc"><span class="tm-cc-code">CC4</span><span class="tm-cc-name">Monitoring activities</span><p class="tm-cc-text">Vanta tests the controls against the infrastructure continuously and flags any drift for remediation.</p><a href="/compliance/Policies/operations-security/">Operations security →</a></div>

## Data protection

| Area | How it is protected |
| --- | --- |
| **Encryption in transit** | TLS 1.2 at a minimum and TLS 1.3 supported on every public endpoint, with HTTP redirected to HTTPS. Production load balancers use AWS's FIPS security policy with hybrid post-quantum key exchange. The message bus between services requires TLS, and internal control-plane calls use mutual TLS. |
| **Encryption at rest** | AES-256 in object storage (Amazon S3), the metadata database (Amazon Aurora PostgreSQL) and storage volumes. |
| **Customer isolation** | Each project has its own database in the data catalog and its own storage prefix. Every query is parsed before it runs, and any reference outside the project, unless the data was explicitly shared with it, is rejected. See [Where your data lives](/architecture/data-storage/). |
| **Source systems** | Teramot only reads from your sources, and a read-only database user is recommended. Private connections over IPsec are available. |
| **Source credentials** | Encrypted at rest, used only when connecting, never returned by the API, and scrubbed from logs and error reports. |
| **Residency** | AWS us-east-1 (N. Virginia). Customer data is not replicated to other regions. |
| **Artificial intelligence** | Teramot does not train or fine-tune models on your data. What each agent receives, and which providers process it, is in [AI agents](/architecture/ai-agents/). |
| **Retention** | Infrastructure logs 365 days, project activity log 90 days, agent traces 14 days, metadata backups 7 days. See [Retention and deletion](/architecture/retention/). |

## Secure development lifecycle

Every change to the product follows the same path to production:

<div class="tm-flow-box not-prose">
<ol class="tm-flow">
  <li><span class="tm-flow-title">Branch</span><span class="tm-flow-text">Work starts on its own branch. The main branch cannot be force-pushed or deleted.</span></li>
  <li><span class="tm-flow-title">Pull request</span><span class="tm-flow-text">Code merges only through a pull request, with linear history and every review thread resolved.</span></li>
  <li><span class="tm-flow-title">Automated checks</span><span class="tm-flow-text">Tests, type checks and linters with security rules (gosec, Bandit), plus secret scanning on the core application.</span></li>
  <li><span class="tm-flow-title">Security review</span><span class="tm-flow-text">A required automated review with a security checklist: credentials, input validation, sensitive data in logs.</span></li>
  <li><span class="tm-flow-title">Staging</span><span class="tm-flow-text">Infrastructure is code (Terraform). Changes reach development and staging before production.</span></li>
  <li><span class="tm-flow-title">Release</span><span class="tm-flow-text">Production runs only versioned releases tagged on signed commits, deployed with short-lived credentials.</span></li>
</ol>
</div>

Container images are scanned for vulnerabilities when they are pushed, and features can be switched off at runtime without a redeploy.

## Monitoring and incident response

| Signal | Coverage |
| --- | --- |
| **Cloud audit trail** | AWS CloudTrail across every region, with log-file integrity validation |
| **Network** | VPC Flow Logs on all production traffic |
| **Threat detection** | Amazon GuardDuty, with findings routed to the security team |
| **Application** | Error monitoring with secrets scrubbed, a correlation ID on every request, and alarms on errors, latency and database health |
| **Endpoints** | Bitdefender GravityZone on staff devices |
| **Compliance** | Vanta tests the controls continuously |

When something does happen, the [Incident Response Plan](/compliance/Policies/incident-response/) sets the steps:

<div class="tm-flow-box not-prose">
<ol class="tm-flow tm-flow-5">
  <li><span class="tm-flow-title">Detect</span><span class="tm-flow-text">Alerts from the monitoring above, or a report to security<wbr>@teramot.com.</span></li>
  <li><span class="tm-flow-title">Triage</span><span class="tm-flow-text">Each incident gets a severity from P0 to P3, which sets its urgency.</span></li>
  <li><span class="tm-flow-title">Contain and fix</span><span class="tm-flow-text">Cybersecurity and DevOps isolate the cause and remediate it.</span></li>
  <li><span class="tm-flow-title">Notify</span><span class="tm-flow-text">Affected customers hear from us within 72 hours of confirmation.</span></li>
  <li><span class="tm-flow-title">Learn</span><span class="tm-flow-text">A written post-incident report. The root-cause analysis is shared under NDA.</span></li>
</ol>
</div>

The plan is tested at least once a year.
