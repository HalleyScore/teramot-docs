## Protección de datos

| Área | Cómo se protege |
| --- | --- |
| **Cifrado en tránsito** | TLS 1.2 como mínimo y TLS 1.3 disponible en todos los endpoints públicos, con HTTP redirigido a HTTPS. Los balanceadores de producción usan la política de seguridad FIPS de AWS con intercambio de claves híbrido post-cuántico. El bus de mensajes entre servicios exige TLS, y las llamadas internas del plano de control usan TLS mutuo. |
| **Cifrado en reposo** | AES-256 en el almacenamiento de objetos (Amazon S3), la base de metadatos (Amazon Aurora PostgreSQL) y los volúmenes. |
| **Aislamiento entre clientes** | Cada proyecto tiene su propia base en el catálogo de datos y su propio prefijo de almacenamiento. Cada consulta se analiza antes de ejecutarse, y se rechaza cualquier referencia fuera del proyecto, salvo datos compartidos explícitamente con él. Ver [Dónde viven tus datos](/es/architecture/data-storage/). |
| **Sistemas de origen** | Teramot solo lee de tus fuentes, y se recomienda un usuario de base de datos de solo lectura. Hay conexiones privadas por IPsec disponibles. |
| **Credenciales de las fuentes** | Cifradas en reposo, usadas solo al conectarse, nunca devueltas por la API y eliminadas de los logs y reportes de errores. |
| **Residencia** | AWS us-east-1 (Virginia del Norte). Los datos de clientes no se replican en otras regiones. |
| **Inteligencia artificial** | Teramot no entrena ni ajusta modelos con tus datos. Qué recibe cada agente, y qué proveedores lo procesan, está en [Agentes de IA](/es/architecture/ai-agents/). |
| **Retención** | Logs de infraestructura 365 días, registro de actividad del proyecto 90 días, trazas de agentes 14 días, backups de metadatos 7 días. Ver [Retención y borrado](/es/architecture/retention/). |

## Ciclo de desarrollo seguro

Cada cambio en el producto sigue el mismo camino a producción:

<div class="tm-flow-box not-prose">
<ol class="tm-flow">
  <li><span class="tm-flow-title">Rama</span><span class="tm-flow-text">El trabajo empieza en su propia rama. La rama principal no admite force-push ni borrado.</span></li>
  <li><span class="tm-flow-title">Pull request</span><span class="tm-flow-text">El código entra solo por pull request, con historia lineal y todos los hilos de revisión resueltos.</span></li>
  <li><span class="tm-flow-title">Controles automáticos</span><span class="tm-flow-text">Tests, chequeo de tipos y linters con reglas de seguridad (gosec, Bandit), más detección de secretos en la aplicación principal.</span></li>
  <li><span class="tm-flow-title">Revisión de seguridad</span><span class="tm-flow-text">Una revisión automática obligatoria con checklist de seguridad: credenciales, validación de entradas, datos sensibles en logs.</span></li>
  <li><span class="tm-flow-title">Staging</span><span class="tm-flow-text">La infraestructura es código (Terraform). Los cambios pasan por desarrollo y staging antes de producción.</span></li>
  <li><span class="tm-flow-title">Release</span><span class="tm-flow-text">Producción corre solo versiones etiquetadas sobre commits firmados, desplegadas con credenciales de corta duración.</span></li>
</ol>
</div>

Las imágenes de contenedores se escanean en busca de vulnerabilidades al subirlas, y las funcionalidades se pueden apagar en tiempo real sin redesplegar.

## Monitoreo y respuesta a incidentes

| Señal | Cobertura |
| --- | --- |
| **Auditoría de la nube** | AWS CloudTrail en todas las regiones, con validación de integridad de los logs |
| **Red** | VPC Flow Logs de todo el tráfico de producción |
| **Detección de amenazas** | Amazon GuardDuty, con hallazgos enviados al equipo de seguridad |
| **Aplicación** | Monitoreo de errores con secretos eliminados, un ID de correlación por pedido y alarmas de errores, latencia y salud de las bases |
| **Equipos** | Bitdefender GravityZone en los equipos del personal |
| **Cumplimiento** | Vanta evalúa los controles de forma continua |

Cuando algo pasa, el [Plan de Respuesta a Incidentes](/es/compliance/Policies/incident-response/) define los pasos:

<div class="tm-flow-box not-prose">
<ol class="tm-flow tm-flow-5">
  <li><span class="tm-flow-title">Detectar</span><span class="tm-flow-text">Alertas del monitoreo de arriba, o un reporte a security<wbr>@teramot.com.</span></li>
  <li><span class="tm-flow-title">Clasificar</span><span class="tm-flow-text">Cada incidente recibe una severidad de P0 a P3, que fija su urgencia.</span></li>
  <li><span class="tm-flow-title">Contener y corregir</span><span class="tm-flow-text">Ciberseguridad y DevOps aíslan la causa y la corrigen.</span></li>
  <li><span class="tm-flow-title">Notificar</span><span class="tm-flow-text">Los clientes afectados reciben aviso dentro de las 72 horas de confirmado.</span></li>
  <li><span class="tm-flow-title">Aprender</span><span class="tm-flow-text">Un informe escrito posterior al incidente. El análisis de causa raíz se comparte bajo NDA.</span></li>
</ol>
</div>

El plan se prueba al menos una vez por año.
